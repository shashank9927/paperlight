# Paperlight production-hardening audit

**2026-10-23 — production hardening complete for the documented support scope.** The existing twelve-tool interface and client-only architecture are preserved. The production build and Nginx image are verified locally. No public deployment was made. Physical-device and provider-specific coverage limits are listed below.

## Fixed findings

- **Document preservation:** merge, split, organize and rotate use bundled QPDF 12.2.0. Assembly rejects forms, internal destinations, bookmarks, attachments, tags and other structures whose preservation is unsupported. Tests cover ordered/duplicate pages, URI links, annotations, page labels, and same-document form values and appearances. Added content uses pdf-lib with shared preview/output geometry, independently rendered at every quarter turn with offset CropBox/MediaBox, resized previews, CSS zoom and DPR 2.
- **Password correctness:** AES-256 revision 6, exact UTF-8 validation, random nonempty owner passwords, independent wrong/missing/empty-password rejection, and complete decryption. Permissions-only encryption is detected. Fixed the bundled QPDF encrypted-probe behavior and WebKit error classification by intercepting WASM output descriptors directly. Only a bounded password-error classifier is retained; diagnostics are suppressed. Removed the confirmation field's 120-character cap and tested the supported 127-byte boundary end to end.
- **Hostile-input and resource controls:** disposable admission workers validate PDFs before preview. Guarded pdf-lib parsing bounds recursive objects, strings/names/numbers, object/xref streams, decompression and page trees before unsafe expansion or traversal. QPDF WASM linear memory is capped at 512 MiB; output writes are bounded before growth. Inspection and processing have 30-second and 120-second deadlines. Malformed documents are rejected without silent recovery. Cancellation/reset release workers, canvases and preview documents; stale jobs cannot publish results.
- **Image and compression correctness:** fixed valid WebP rejection caused by decoding RIFF binary length bytes as text. Header dimensions are checked before image decode, EXIF orientation is honored, PNG transparency and white JPEG backgrounds are tested. Default compression remains lossless; rasterization is explicit. Both modes run on text-heavy, scanned, image-heavy/mixed and already-optimized fixtures. Savings use actual sizes and non-improving compression returns exact original bytes, including encryption.
- **Production hosting:** added a real unprivileged Nginx image and explicit routes, asset 404s, JavaScript/WASM MIME types and restrictive headers. Production testing found and fixed `.mjs` worker MIME handling. Small font subsets now remain same-origin files instead of conflicting with CSP. Hosting checks cover all 13 routes and every emitted script/module worker; browser tests assert no CSP violations. Warm offline processing works for every tool with network observation covering workers and service workers.
- **Reproducibility:** corrected the invalid development-container base image, pinned parser/engine-sensitive versions, added the verified WASM memory adapter and fixed cross-platform lockfile entries. CI covers processing, strict browser capabilities, separate benchmarks and the production host. Browser downloads are cached. The cached images can package the final build with networking disabled.

The initial dependency audit reported four advisories. PDF.js was upgraded from 5.7.284 to 6.4.299, Vitest from 3.2.7 to 4.1.12, and native canvas aligned to 1.0.13. The latest audit reports zero. Exact installed versions, QPDF binary output, original/generated WASM hashes and random-provider checks are in [dependency evidence](evidence/dependencies.json). The memory adapter changes the verified binary's memory declaration; it does not replace QPDF's processing or encryption code.

The first production run found a test synchronization issue: Firefox reports worker closure asynchronously. That assertion now waits for the event and passed in the next full run. The next run exposed a fast-job click race: a tiny WebKit job completed before the automated Cancel click. That regression now holds the first three real workers pending, checks their termination on cancel, and processes the final replacement normally; it passed three repeats in each engine. A separate unmodified test covers cancellation during normal processing. No application change was needed for these two test timing issues. The earlier Linux run's actual encrypted-input failure was fixed in application code; WebKit password, length-boundary and CSP flows then passed [nine repeated checks](evidence/password-verification.txt). Every downloaded PDF and PDF inside a split ZIP receives independent structural/text checks; unencrypted output receives a Poppler render. Image exports are independently decoded. ## Measured performance

Linux under WSL2, AMD Ryzen 7 7840HS; verification container limited to 4 CPU cores, 6 GiB RAM and 1 GiB shared memory. Node 24.22.1; actual Nginx production build on loopback, no throttling. The fixture is 809,787 bytes and three pages: selectable text, a rotated/cropped text page and a seeded scan. Preview timing includes admission and completed rendering; processing measures lossless compression. Values are medians in milliseconds across three cold/warm pairs.

[Summary and host data](evidence/production-benchmark-summary.json); raw samples are linked in the evidence index. All samples satisfy the existing measured regression budgets: 2 seconds load, 3.5 seconds preview, 2.5 seconds processing and 250 ms event-loop interval. No pre-change speedup is claimed. Chromium's largest reported page JavaScript heap was 35.1 MB; Firefox/WebKit do not expose it. That metric excludes workers, WASM, native and GPU allocations and is not peak process memory.

The 100 MiB and 500-page boundary fixtures are tested separately in every desktop engine. The 100 MiB fixture contains valid auxiliary streams and one page; the 500-page fixture is simple. Their completion proves those boundaries work for these inputs, not that a complex 500-page scan will fit a phone. Compression corpus measurements are synthetic and make no universal compression-ratio claim.

The verification container's lifetime peak was **5,242,630,144 bytes (4.88 GiB)** with zero OOM events. This includes parallel browsers, fixture generation, Python and Poppler across repeated runs, not just application memory. [Recorded resource scope](evidence/verification-resources.json). The release has 250 static files totaling 9,881,399 bytes; [artifact hashes](evidence/release-artifact.json) identify the tested image and lockfile.

## Supported limits and release scope

Input is capped at **100 MiB combined / 500 pages**. Additional ceilings include 16 MP / 8192-pixel input images, 4096-pixel raster output sides, 120 MP aggregate raster work, 128 MiB encoded output/ZIP, 100,000 parsed objects, 64 MiB per decoded stream / 256 MiB cumulative stream decoding, and 24 preview canvases / 8 MP with two active renders. QPDF's 512 MiB WASM cap does not include JavaScript filesystem buffers. See [the preservation and resource matrix](PRESERVATION.md) for exact support and rejection rules.

No known failing product check remains within the verified support scope. Scope limits remain explicit:

- Actual macOS Safari, iOS Safari, Android hardware, pinch zoom and low-memory phone profiling were unavailable. Linux WebKit is an automated engine, not a physical Safari device. Windows Playwright WebKit lacks worker OffscreenCanvas; that port is unsupported for raster tools. The Linux matrix closes the previous Firefox/WebKit automated coverage gap without claiming hardware coverage.
- Complex PDF assembly, XFA editing, certified signatures, PDF/A/PDF/UA certification and sanitization are outside this release. Unsupported assembly structures are rejected. Full bookmark/attachment/tag behavior and compatibility with every PDF producer are not certified; the [support matrix](PRESERVATION.md) distinguishes tested preservation from retained-but-unverified structures.
- The local Linux environment and Nginx artifact were exercised. Hosted GitHub Actions and a public HTTPS provider were not run. A different deployment must validate its own HTTPS, routing, MIME, headers and service-worker update behavior. No public deployment was made.

The [requirement-to-test matrix](REQUIREMENTS-TESTS.md) maps the twelve tools to evidence. [Setup instructions](SETUP.md) include cached-container reuse and offline packaging, so normal verification does not repeat large downloads. No guarantee of secure erasure of browser memory is made.
