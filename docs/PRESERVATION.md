# Document support and preservation

These are deliberately bounded claims for the installed versions recorded in [dependency evidence](evidence/dependencies.json). Passing the fixture corpus is not proof for every PDF producer. No operation is a sanitizer, PDF/A validator, PDF/UA validator, or certificate signing service.

Encryption, including an empty opening password, is detected in the admission worker with QPDF and confirmed by PDF.js metadata. The bundled QPDF password-error probe behavior has a regression test. The tool informs the user that the export will be unprotected. Protect generates a separate 256-bit random owner password. The opening password is nonempty, and its exact UTF-8 representation is limited to 127 bytes. Null characters and malformed surrogate sequences are rejected. No normalization, trimming, truncation, or `ignoreEncryption` is used.

Compression has an exception to plaintext export: when output would be as large as or larger than the input, the result is the **exact original bytes**, retaining original encryption. The result explains this and always offers the original separately. Savings and sizes use actual byte lengths.

## Selection and placement

- Empty range means all input pages. Explicit ranges preserve written order; repeated numbers are ignored. Descending intervals are invalid. Organize permits deliberate duplicates and uses displayed order for extraction.
- Numbering advances through selected pages in range order, not original page positions. With start `8` and range `4,2,1,3`, pages 1–4 receive `10,9,11,8`. The total style displays the final counter value, e.g. `8 / 11`.
- Placement uses the visible intersection of CropBox and MediaBox, including nonzero origins. Rotation is applied in PDF coordinates; CSS preview scales the same normalized visible positions independently of device pixel ratio. All quarter turns are rendered with Poppler in E2E tests. Preview resizing and DPR 2 are covered. CSS zoom at 125% is also covered; browser-toolbar zoom and physical-device pinch zoom remain unverified.
- Non-default PDF UserUnit is rejected for annotation/raster operations. Invalid rotated/page geometries and obscure encodings may be rejected by the parser. Text uses bundled Liberation Sans; unsupported characters fail rather than rendering missing glyphs. Unicode filenames are independent of glyph support.
- Images use decoded EXIF orientation. Fit-to-image dimensions are based on the oriented original pixel dimensions at 96 pixels/inch, even when the embedded bitmap is downscaled. Transparent PNGs remain transparent; JPEG page exports use white backgrounds. No OCR is applied.

## Limits and resource ownership

| Limit                                                                                   | Enforced location                                                                                             |
| --------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| 100 MiB combined input; 500 input/output pages                                          | Workspace plus processing worker; actual PDF page counts rechecked                                            |
| 16 million decoded pixels per input image, 8192 pixels per side                         | Bounded PNG/JPEG/WebP header inspection before decoding, plus decoded-size check                              |
| 4096 pixels longest raster output side; at most 16,777,216 canvas pixels                | Raster renderer and PDF.js auxiliary canvas factory                                                           |
| 120 million total raster pixels / image-input pixels per job                            | Sequential worker loop                                                                                        |
| 128 MiB accumulated encoded outputs and final ZIP                                       | Before retaining results, before/after ZIP creation, and on each QPDF virtual-file write before output growth |
| 100,000 PDF objects; 10,000 annotations per page                                        | Parsed structure preflight; includes inline dictionaries                                                      |
| 2 active preview renders; 24 retained preview canvases; 8 million preview canvas pixels | Shared preview budget, lazily allocated; offscreen/unmounted canvases released                                |
| 10 MiB signature upload; 16 million input pixels; 1600 pixels longest signature side    | Signature upload validation and conversion                                                                    |

Additional admission limits: 64 MiB per decoded stream, 256 MiB cumulative decoded stream data, four filter stages, nesting depth 64, one million parser tokens, 1 MiB strings, 1024-byte names and 128-byte numeric tokens. Object/xref streams are bounded before pdf-lib decodes them. Cyclic page trees, dishonest page counts, oversized images and invalid page geometry are rejected before PDF.js preview. Compressed font data shares the stream budget. QPDF's verified WASM binary is generated with a 512 MiB memory maximum; its virtual filesystem and JavaScript allocations are separate. Admission workers have a 30-second deadline and processing workers a two-minute deadline.

These are ceilings, not a promise that every device can process every file at the ceiling. Synthetic 100 MiB and 500-page jobs are exercised in the browser matrix. Decompression bombs, recursive structures, excessive object counts and oversized image headers have regression tests. The limits bound specific allocations; they are not a total browser-process, GPU or native decoder memory cap. Malformed image codecs and unusual fonts remain subject to browser/library limits. Physical low-memory phones have not been qualified.

File admission runs in a disposable worker before preview. Each processing job owns its worker, input byte arrays, QPDF instance and virtual files. Preview parsing owns separate buffers; no preview/retry buffer is transferred to the processing worker. Output transfers happen once. QPDF files are unlinked in `finally`; job workers terminate on completion, error or cancellation. Preview tasks are abortable during file replacement/reset; the shared parser worker closes when its last document is released. Signature generations prevent stale asynchronous results. No guarantee of secure memory erasure is made.

Raster processing requires worker `OffscreenCanvas`, `convertToBlob` and `createImageBitmap`. Linux Chromium, Firefox and WebKit expose these APIs and run the complete raster suite. Windows Playwright WebKit does not expose OffscreenCanvas; that test port remains unsupported for raster tools. There is no main-thread or remote-conversion fallback. The release suite sets `PAPERLIGHT_STRICT_BROWSERS=1`, turning a missing API into a failure instead of a skip. Actual Safari/iOS/Android device testing is separate from these automated browser engines.
