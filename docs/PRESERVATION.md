# Document support and preservation

These are deliberately bounded claims for the installed versions recorded in [dependency evidence](evidence/dependencies.json). Passing the fixture corpus is not proof for every PDF producer. No operation is a sanitizer, PDF/A validator, PDF/UA validator, or certificate signing service.

Encryption, including an empty opening password, is detected in the admission worker with QPDF and confirmed by PDF.js metadata. The bundled QPDF password-error probe behavior has a regression test. The tool informs the user that the export will be unprotected. Protect generates a separate 256-bit random owner password by default. Advanced controls accept an independent owner password and printing, copying, editing, annotation, form and assembly permissions. These permissions depend on viewer enforcement; they do not prevent screenshots or guarantee copy prevention. Explicit permissions-only mode allows an empty opening password and requires an owner password. Otherwise the opening password is nonempty, and its exact UTF-8 representation is limited to 127 bytes. Null characters and malformed surrogate sequences are rejected. No normalization, trimming, truncation, or `ignoreEncryption` is used.

Compression has an exception to plaintext export: when output would be as large as or larger than the input, the result is the **exact original bytes**, retaining original encryption. The result explains this and always offers the original separately. Savings and sizes use actual byte lengths.

## Selection and placement

- Empty range means all input pages. Explicit ranges preserve written order; repeated numbers are ignored. Descending intervals are invalid. Organize permits deliberate duplicates and uses displayed order for extraction.
- Numbering advances through selected pages in range order, not original page positions. With start `8` and range `4,2,1,3`, pages 1–4 receive `10,9,11,8`. The total style displays the final counter value, e.g. `8 / 11`.
- Placement uses the visible intersection of CropBox and MediaBox, including nonzero origins. Rotation is applied in PDF coordinates; CSS preview scales the same normalized visible positions independently of device pixel ratio. All quarter turns are rendered with Poppler in E2E tests. Preview resizing and DPR 2 are covered. CSS zoom at 125% is also covered; browser-toolbar zoom and physical-device pinch zoom remain unverified.
- Non-default PDF UserUnit is rejected for annotation/raster operations. Invalid rotated/page geometries and obscure encodings may be rejected by the parser. Text uses bundled Liberation Sans, Serif and Mono plus an italic signature choice; unsupported characters fail rather than rendering missing glyphs. Unicode filenames are independent of glyph support.
- Images use decoded EXIF orientation. Fit-to-image dimensions are based on the oriented original pixel dimensions at 96 pixels/inch, even when the embedded bitmap is downscaled. Transparent PNGs remain transparent; JPEG page exports use white backgrounds. No OCR is applied.

## Limits and resource ownership

| Limit                                                                                   | Enforced location                                                                                             |
| --------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| 100 MiB combined input; 500 input/output pages                                          | Workspace plus processing worker; actual PDF page counts rechecked                                            |
| 16 million decoded pixels per input image, 8192 pixels per side                         | Bounded PNG/JPEG/WebP header inspection before decoding, plus decoded-size check                              |
| 4096 pixels longest raster output side; at most 16,777,216 canvas pixels                | Raster renderer and PDF.js auxiliary canvas factory                                                           |
| 120 million total raster pixels / image-input pixels per job                            | Sequential worker loop                                                                                        |
| 128 MiB accumulated encoded outputs and final ZIP                                       | Before retaining results, before/after ZIP creation, and on each QPDF virtual-file write before output growth |
| 100,000 PDF objects; 10,000 annotations per page                                        | Parsed structure preflight; includes inline dictionaries                                                      |
| 2 active preview renders; 24 retained preview canvases; 8 million preview canvas pixels | Shared preview budget, lazily allocated; offscreen/unmounted canvases released                                |
| 10 MiB signature upload; 16 million input pixels; 1600 pixels longest signature side    | Signature upload validation and conversion                                                                    |

Additional admission limits: 64 MiB per decoded stream, 256 MiB cumulative decoded stream data, four filter stages, nesting depth 64, one million parser tokens, 1 MiB strings, 1024-byte names and 128-byte numeric tokens. Object/xref streams are bounded before pdf-lib decodes them. Cyclic page trees, dishonest page counts, oversized images and invalid page geometry are rejected before PDF.js preview. Compressed font data shares the stream budget. QPDF's verified WASM binary is generated with a 512 MiB memory maximum; its virtual filesystem and JavaScript allocations are separate. Admission workers have a 30-second deadline and processing workers a two-minute deadline.

These are ceilings, not a promise that every device can process every file at the ceiling. Synthetic 100 MiB and 500-page jobs are exercised in the browser matrix. Decompression bombs, recursive structures, excessive object counts and oversized image headers have regression tests. The limits bound specific allocations; they are not a total browser-process, GPU or native decoder memory cap. Malformed image codecs and unusual fonts remain subject to browser/library limits. Physical low-memory phones have not been qualified.

File admission runs in a disposable worker before preview. Each processing job owns its worker, input byte arrays, QPDF instance and virtual files. Preview parsing owns separate buffers; no preview/retry buffer is transferred to the processing worker. Output transfers happen once. QPDF files are unlinked in `finally`; job workers terminate on completion, error or cancellation. Preview tasks are abortable during file replacement/reset; the shared parser worker closes when its last document is released. Signature generations prevent stale asynchronous results. No guarantee of secure memory erasure is made.

Raster processing requires worker `OffscreenCanvas`, `convertToBlob` and `createImageBitmap`. Linux Chromium, Firefox and WebKit expose these APIs and run the complete raster suite. Windows Playwright WebKit does not expose OffscreenCanvas; that test port remains unsupported for raster tools. There is no main-thread or remote-conversion fallback. The release suite sets `PAPERLIGHT_STRICT_BROWSERS=1`, turning a missing API into a failure instead of a skip. Actual Safari/iOS/Android device testing is separate from these automated browser engines.

## Redesign additions

- Image optimization uses QPDF's verified bundled optimizer with JPEG quality 90/75/50 and preserves text/vector operators. Lossless remains the initial selection. Whole-page rasterization is a separate, disclosed option. Exact-original fallback and existing preservation guards apply to all modes.
- Size splitting measures the actual serialized PDF for every candidate group. It explicitly reports the page number when one page exceeds the limit. Optional lossy compression is applied only in size mode, after explicit selection. Custom groups may repeat pages across groups but share the 500-output-page ceiling.
- Organize represents imported and blank pages explicitly. Blank pages are synthesized locally and assembled through QPDF. Bookmarks, destinations and supported page/annotation tag trees use the preservation assembler. Forms and other unverified structures remain restricted.
- Numbering tokens: `{n}` current counter; `{p}` original document page count; `{r}` selected-page count after cover exclusion; `{rf}` final counter. An excluded first-page cover is never counted. Facing-page mirroring starts after that cover. Text geometry uses the same normalized positions in the preview and export.
- Embedded-image extraction targets decoded image data, not every visual object on a page. Repeated image objects are deduplicated per page, inline images are decoded, and soft-mask alpha is retained for PNG. Stencil masks export as monochrome artwork. Vectors, patterns, shadings and page text are not extracted images; use page rendering for full appearance. JPEG flattens transparency onto white. The adapter is pinned to PDF.js 6.4.299 and must be reverified on upgrades.
- Signature fields have independent type, page targets, normalized geometry, style and asset bytes. Same geometry drives preview/export. They are visual marks, not certificate-backed signatures. There are at most 500 fields and 2,000 expanded page placements. Combined annotation assets are limited to 32 MiB.
- Uploaded artwork: raster inputs at most 10 MiB; SVG at most 1 MiB and 2,000 elements, bounded to 8192 pixels/16 MP, then locally rasterized to at most 1600 pixels per side. Only static shape/gradient/path content is accepted. Scripts, events, external links, embedded images, text, filters, foreign objects, entities and active content are rejected. Original SVG never enters the output PDF.
- Batches share input, page, pixel and output ceilings and run documents sequentially. Individual failures are explicit. Successful files alone enter a partial-results ZIP, prefixed with source order to avoid filename collisions. Cancellation/deadline terminates active work and discards accumulated results. Batch output buffers are in-memory only.
- The worker boundary uses tool-specific typed configurations and a whitelist; the settings editor retains a compatibility draft of defaults. Only the selected tool's settings enter the worker request. All processing inputs are validated again in the worker.
- Only appearance preference persists. Static Inter and annotation fonts are cached with the application; PDFs, credentials, artwork and editing histories are never stored in caches or browser storage.

## Preservation-aware assembly update

See [PRESERVATION-RELEASE.md](PRESERVATION-RELEASE.md) for the expanded support, final verification evidence, and precise remaining restrictions. The current table and release document describe the verified preservation boundaries.

Assembly keeps the first selected source’s document information and view metadata; bookmarks/navigation and supported tag data are combined from every selected source. Matching document-wide ICC output conditions are retained; conflicting conditions require a color-managed editor. Generated blank pages count against output limits, not external input page counts. Pre-serialization/object/string/traversal budgets can conservatively reject a file before an oversized allocation, even if later compression might reduce it.
