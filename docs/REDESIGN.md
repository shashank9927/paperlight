# Paperlight redesign and local tool completion

Current ordinary-document compatibility and the lecture-file verification are described in [COMPATIBILITY.md](COMPATIBILITY.md). Its selection/form/layer/media behavior supersedes earlier rejection cases below; dated release evidence remains historical.

Release date: 2026-10-23. This release implements the agreed on-device scope for the twelve existing routes. It keeps React, TypeScript, PDF.js 6.4.299, bundled QPDF 12.2.0, isolated workers, preservation guards and the no-upload architecture. Public deployment, cloud imports, AI services, signature requests and certified signing are excluded by the agreed scope.

## Interface

Self-hosted Inter, shared neutral surface/control tokens, restrained indigo accents, consistent focus states and a dark/light theme toggle replace the previous mixed-font/pastel design. Dark is the initial theme. Previously saved System preferences continue following the operating system until toggled, then become an explicit Dark or Light preference. Only `paperlight-theme` persists. The searchable/category-filtered directory leads into the same file → configure → process → result workflow. Settings collapse on small screens; ordering and annotation placement have keyboard/button alternatives to dragging. PDF pages remain white, with document colors independent of appearance.

Visual/automated coverage includes 390, 768 and 1440 CSS-pixel widths, both themes, empty/populated/error/processing/result states, reduced motion, accessible names, focus handling, contrast and horizontal overflow. Screenshot capture waits for rendered preview canvases. Representative images are retained with release evidence. Automated browser emulation does not establish physical-phone qualification or complete screen-reader conformance.

## Architecture and supported limits

Tool-specific interfaces and the `ConfiguredJob` discriminated union whitelist settings at the worker boundary. Shared editor components use a normalized in-memory compatibility draft; unrelated options do not cross the worker boundary. Processing validates again. Annotation geometry/styles/assets, batch entries and blank/imported page references have explicit types.

Fonts are locally bundled and licensed: Inter for the interface; Liberation Sans, Serif and Mono for PDF text, plus italic Serif for the signature choice. Missing glyphs fail explicitly. Static SVG accepts bounded shapes/paths/gradients only; it rejects active content, external references and XML processing instructions before rasterizing locally. SVG text must first be outlined.

`{n}` is the current counter, `{p}` the document page count, `{r}` the selected-page count after excluded cover removal and `{rf}` the final counter. The cover never advances numbering. Embedded-image extraction exports decoded raster objects; text, vectors and page-level effects require page rendering. Compression ratios and exact font families do not claim identity with iLovePDF.

All previous preservation exclusions, deadlines and resource limits remain. See [PRESERVATION.md](PRESERVATION.md). Actual macOS/iOS Safari, Android hardware, low-memory phones, physical pinch zoom and hosted-provider behavior remain unverified. Linux WebKit is an engine check, not physical Safari certification. Windows Playwright WebKit still lacks worker OffscreenCanvas for raster tools. Viewer-dependent PDF permissions do not enforce confidentiality once a document is open.
